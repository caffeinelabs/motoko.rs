# AGENTS.md

Motoko tools for Rust: a library (`motoko` crate) for lexing, parsing, and interpreting the Motoko language, plus a `mo-rs` CLI.

## Layout

This is a Cargo workspace. Non-obvious directories:

- `crates/motoko/` — the main `motoko` library crate and the `mo-rs` binary.
- `crates/motoko_proc_macro/` — procedural macros used by the library.
- `crates/motoko/src/packages/` — generated package data; see "Generated files".
- `node/` — a Node script used only to regenerate `crates/motoko/src/packages/`.
- `submodules/` — git submodules (`dfinity/motoko`, `dfinity/motoko-base`) required by the package generator.
- `docs/` — language grammar reference.

## Build, test, lint, format

Run from the repository root:

- Build: `cargo build`
- Test: `cargo test`
- Format: `cargo fmt`
- Lint: `cargo clippy`

CI (`.github/workflows/rust.yml`) builds and tests on the **nightly** toolchain with `rustfmt` and `clippy` components, so use nightly to match CI.

The `mo-rs` binary requires the `exe` feature: `cargo run --features exe --bin mo-rs`.

Benchmarks: `cargo bench` in `crates/motoko` (benchmark name `benchmark`).

## Generated files — do not hand-edit

- `crates/motoko/src/lib/parser.rs` is generated from `parser.lalrpop` by the build script (`build.rs`) via LALRPOP. It is gitignored; do not commit or edit it.
- `crates/motoko/src/packages/*.json` and `prim.mo` are generated by `node/generate.js`. To regenerate: initialize submodules (`git submodule update --init`), then from `node/` run `npm install` and `npm run generate`.

## Conventions and gotchas

- `Cargo.lock` is gitignored (this is primarily a library).
- Cargo features gate functionality: `default = ["parser", "to-motoko"]`; `exe` enables the CLI, and reflection/serde-paths are opt-in.
- Dependency licenses are enforced in CI by cargo-deny (`.github/workflows/license.yml`), which runs `check bans licenses sources`. New dependencies must pass these checks.
