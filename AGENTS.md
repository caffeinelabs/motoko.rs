# AGENTS.md

`motoko.rs` is a Rust library and CLI that lexes, parses, and interprets the Motoko language.

## Layout

- `crates/motoko` — the `motoko` library (`src/lib`) and the `mo-rs` binary (`src/bin`, requires the `exe` feature).
- `crates/motoko_proc_macro` — procedural macros used by the library.
- `node` — a Node.js script that regenerates Motoko package data checked into `crates/motoko/src/packages/`.
- `submodules` — git submodules (`dfinity/motoko`, `dfinity/motoko-base`) that the generator reads from.
- `docs/grammar.txt` — reference grammar.

## Build & test

- Build: `cargo build`
- Test: `cargo test`
- The CI toolchain is Rust **nightly** with `rustfmt` and `clippy` components.
- For verbose test logging (matches the `tests/README.md` convention): `RUST_LOG=trace cargo test -- --nocapture`. Tests that use it declare `use test_log::test;`.
- Benchmarks live in `crates/motoko/benches` (Criterion); run with `cargo bench` from `crates/motoko`.

## CI checks

- `cargo build` and `cargo test` run on push/PR to `main`.
- License/dependency check runs `cargo-deny check bans licenses sources`; keep licenses and sources compliant.

## Generated files — do not hand-edit

- `crates/motoko/src/lib/parser.rs` is generated from `src/lib/parser.lalrpop` by `build.rs` at build time.
- `crates/motoko/src/packages/{base,base-test,matchers}.json` and `prim.mo` are generated by `node/generate.js`. To refresh them, initialize the submodules, then from `node/` run `npm install` and `npm run generate`.

## Conventions

- Rust workspace on edition 2018; the library is licensed Apache-2.0.
- The library's default features are `parser` and `to-motoko`; the CLI binary needs `--features exe`.
