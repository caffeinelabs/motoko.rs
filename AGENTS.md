# AGENTS.md

Motoko language tooling (lexer, parser, and a partially implemented interpreter) written in Rust.

## Layout

- `crates/motoko` — the main `motoko` library and the `mo-rs` binary.
- `crates/motoko_proc_macro` — proc-macro crate for compile-time Motoko expressions.
- `node/` — Node.js script that regenerates the Motoko package data under `crates/motoko/src/packages/`.
- `submodules/` — git submodules (`motoko`, `motoko-base`) that `node/generate.js` reads from.
- `docs/grammar.txt` — grammar reference.

## Build, test, format, lint

A nightly toolchain is used in CI (`rustfmt` and `clippy` components).

- Build: `cargo build`
- Test: `cargo test`
- Format: `cargo fmt`
- Lint: `cargo clippy`

To see logs from a failing test: `RUST_LOG=trace cargo test -- --nocapture`.

Benchmarks live in `crates/motoko/benches/benchmark.rs` and run via criterion:
`cargo bench` (run from `crates/motoko`).

## Generated files — do not hand-edit

Files under `crates/motoko/src/packages/` (`base.json`, `base-test.json`,
`matchers.json`, `prim.mo`) are generated by `node/generate.js`. To regenerate:

```
cd node
npm install
npm run generate
```

Regeneration reads `submodules/motoko` and `submodules/motoko-base`, so the
submodules must be checked out (`git submodule update --init`).

`crates/motoko/src/lib/parser.rs` is generated from `parser.lalrpop` by the
build script (`build.rs`) via `lalrpop`; it is gitignored. Do not edit it by hand.

## Conventions and gotchas

- `Cargo.lock` is gitignored (this is a library); do not commit it.
- CI runs a license/dependency check with `cargo-deny` (`check bans licenses sources`);
  new dependencies must pass it.
- The library is `Apache-2.0` licensed.
- The default crate features are `parser` and `to-motoko`; the `mo-rs` binary
  requires the `exe` feature (`cargo build --features exe`).
